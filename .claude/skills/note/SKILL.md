# /note — 寫入 Notion 技術筆記

## 觸發時機

使用者輸入 `/note`，後面可能接一段文字，也可能什麼都不接。

## 內容來源

- `/note` 後面有文字 → 那段文字就是這則筆記要記錄的核心內容。
- `/note` 後面沒有文字 → 回顧這個對話**最近一次完成的技術修復或決策**（例如剛修完的 Phase 1
  缺陷、剛做的架構取捨），只抓最近這一段，不要把整個對話歷史都塞進去。

## 固定寫入位置

一律寫進 Notion 頁面「🧪 技術分析」：

- page id: `3c5708da-9f92-80f9-87ca-de36881ec404`
- url: https://app.notion.com/p/3c5708da9f9280f987cade36881ec404
- 這是「Spring Boot MVC購物車專案(玉山2026/8)」底下的子頁。

除非使用者在指令裡明確指定別的地方，否則不要寫到頂層專案頁或其他子頁。如果用這個 id
找不到頁面（結構可能變了），改用 `notion-search` 搜尋「技術分析 esun-shopping」重新定位，
再繼續下面的步驟。

## 寫入方式

這個頁面底下每個主題都是**獨立子頁**（不是同一頁裡分章節）。子頁標題格式是
`{編號} {簡短標題}`，並帶一個對應主題的 emoji icon，例如既有的：

- `⌛ 3.1 Order ID 碰撞：毫秒時間戳 + 隨機尾碼`
- `🧪 4.1 HTTP 狀態碼：全面改正錯誤回應`
- `🧪 4.2 前端 Axios 統一：移除 api.js，環境變數設定`

執行步驟：

1. 用 `notion-fetch` 讀一次「技術分析」頁面，看目前已有哪些子頁、編號規則（例如 3.x 是訂單相關、
   4.x 是驗證/錯誤處理相關），判斷這次筆記該接在哪個系列編號之後，並選一個貼切的 emoji。
   如果從既有編號規則判斷不出歸類，就用這次對話裡提到的 Phase 1 任務編號當後綴（例如任務 9
   → 先用 `9.1`），並在草稿裡標註清楚，讓使用者確認或修改。
2. 用 CLAUDE.md 的 Documentation template 當骨架（Task / Problem / Root Cause / Solution /
   Engineering Concept / Test Result / Trade-offs / Next Step），但比照這個頁面既有子頁的實際寫法調整：
   - 標題用中文（問題 / 解決方案 / 取捨 / Commit 等），八個欄位不必全寫，只寫有內容的。
   - 不要留「[待補]」之類的空白佔位字；沒東西寫的欄位就整節省略。
   - 如果這次修復有對應的 commit，最後加一節 `## Commit`，附上 hash + commit message。
3. 把草稿（標題 + emoji + 內文）先整段貼在對話裡給使用者看，用繁體中文簡短問一句「要照這樣寫進
   Notion 嗎？」再等使用者確認。
   - 例外：如果使用者在 `/note` 之後就明確講了「直接寫」「不用確認」之類的話，才可以跳過確認直接寫入。
4. 使用者確認後，用 `notion-create-pages` 在「技術分析」頁面（parent = page_id
   `3c5708da-9f92-80f9-87ca-de36881ec404`）底下建立新子頁，帶上選好的 icon、title、content。
5. 完成後把新頁面的連結回覆給使用者。

## 注意事項

- 這個 skill 只負責「寫技術筆記」，不要順便改程式碼、跑測試或做其他任務。
- 每次只處理「最近一段」內容，不要把整個對話全部倒進同一篇筆記。
- 如果使用者要記錄的東西明顯跟 esun-shopping 這個專案無關，先確認要寫到哪裡，不要預設寫進
  技術分析頁。
