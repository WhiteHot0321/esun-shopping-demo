# /note — 寫入 Notion 技術筆記

## 觸發時機

使用者輸入 `/note`，後面可能接一段文字，也可能什麼都不接。

## 內容來源

- `/note` 後面有文字 → 那段文字就是這則筆記要記錄的核心內容。
- `/note` 後面沒有文字 → 回顧這個對話**最近一次完成的技術修復或決策**（例如剛修完的 Phase 1
  缺陷、剛做的架構取捨），只抓最近這一段，不要把整個對話歷史都塞進去。

## 固定寫入位置

一律寫進 Notion 頁面「📓 技術筆記」（2026-10-09 前名稱為「提示詞內容分析」）：

- page id: `3ec708da-9f92-80a1-a221-c7593e013303`
- url: https://app.notion.com/p/3ec708da9f9280a1a221c7593e013303
- 位置：「Spring Boot MVC購物車專案(玉山2026/8)」→「🧪 技術分析」→「📓 技術筆記」。
  「技術分析」本身只放兩個子頁（技術筆記、單字解釋），不要把筆記直接建在技術分析底下。

除非使用者在指令裡明確指定別的地方，否則不要寫到頂層專案頁或其他子頁。如果用這個 id
找不到頁面（結構可能變了），改用 `notion-search` 搜尋「技術筆記 esun-shopping」重新定位，
再繼續下面的步驟。架構說明屬於「🏗️ 程式結構」的分層子頁，名詞解釋屬於「單字解釋」，都不寫成筆記。

## 寫入方式

這個頁面底下每個主題都是**獨立子頁**（不是同一頁裡分章節），依主題分在幾個標題區塊下
（基礎技術分析、測試工具、實際並發測試成果、Phase 2 技術重點、Phase 3 之後）。子頁標題格式
沿用既有寫法 `{Phase 或任務編號} — {簡短標題}`，並帶一個對應主題的 emoji icon，例如既有的：

- `Phase 1.#3 — Order ID 碰撞：毫秒時間戳 + 隨機尾碼`
- `Phase 1.5 B — Testcontainers 並發整合測試，並修復 FK 共享鎖升級死鎖 (Commit 9cd487c)`
- Phase 3 起的任務用任務總表編號，例如 `#20 — SQL 效能基線：EXPLAIN ANALYZE 找出推薦查詢的成本`

執行步驟：

1. 用 `notion-fetch` 讀一次「技術筆記」頁面，看目前已有哪些子頁與標題區塊，判斷這次筆記
   該用哪個編號、放在哪個區塊，並選一個貼切的 emoji。判斷不出歸類時，在草稿裡標註清楚，
   讓使用者確認或修改。
2. 用 CLAUDE.md 的 Documentation template 當骨架（Task / Problem / Root Cause / Solution /
   Engineering Concept / Test Result / Trade-offs / Next Step），但比照這個頁面既有子頁的實際寫法調整：
   - 標題用中文（問題 / 解決方案 / 取捨 / Commit 等），八個欄位不必全寫，只寫有內容的。
   - 不要留「[待補]」之類的空白佔位字；沒東西寫的欄位就整節省略。
   - 如果這次修復有對應的 commit，最後加一節 `## Commit`，附上 hash + commit message。
3. 把草稿（標題 + emoji + 內文）先整段貼在對話裡給使用者看，用繁體中文簡短問一句「要照這樣寫進
   Notion 嗎？」再等使用者確認。
   - 例外：如果使用者在 `/note` 之後就明確講了「直接寫」「不用確認」之類的話，才可以跳過確認直接寫入。
4. 使用者確認後，用 `notion-create-pages` 在「技術筆記」頁面（parent = page_id
   `3ec708da-9f92-80a1-a221-c7593e013303`）底下建立新子頁，帶上選好的 icon、title、content。
   新子頁會出現在頁面最下方，也就是「Phase 3 之後」區塊內；不需要再搬動。
5. 完成後把新頁面的連結回覆給使用者。

## 注意事項

- 這個 skill 只負責「寫技術筆記」，不要順便改程式碼、跑測試或做其他任務。
- 每次只處理「最近一段」內容，不要把整個對話全部倒進同一篇筆記。
- 如果使用者要記錄的東西明顯跟 esun-shopping 這個專案無關，先確認要寫到哪裡，不要預設寫進
  技術分析頁。
